<objective>
Implement the dual execution engine supporting Virtual paper simulation and Live Alpaca brokerage execution with integrated pre-trade risk filters and order routing.
</objective>

<tasks>
<task id="1">
<title>Define Execution Models & Broker Base Interface</title>
<action>
Create `src/execution/models.py` and `src/execution/broker_base.py`:
- `Order`: symbol, side (buy/sell), quantity, order_type (market/limit), status, fills
- `Position`: symbol, quantity, entry_price, current_price, pnl
- `AccountInfo`: cash, buying_power, portfolio_value, day_trades_count
- `BaseBroker`: abstract interface for order placement, cancellation, positions, and account info.
</action>
<acceptance_criteria>
- Clean abstract base class with full type hints
</acceptance_criteria>
</task>

<task id="2">
<title>Implement Virtual Broker & Alpaca Broker</title>
<action>
Create `src/execution/virtual_broker.py` and `src/execution/alpaca_broker.py`:
- `VirtualBroker`: in-memory simulation with slippage model, cash accounting, and instant/delayed fills
- `AlpacaBroker`: connects to Alpaca Trading API via REST endpoints for real paper or live execution.
</action>
<acceptance_criteria>
- Virtual broker correctly tracks balances, positions, and P&L
- Alpaca broker maps internal Order objects to Alpaca API format
</acceptance_criteria>
</task>

<task id="3">
<title>Build Execution Engine with Risk Integration</title>
<action>
Create `src/execution/engine.py`:
- `ExecutionEngine`: orchestrates order execution, selects broker mode (Virtual vs Live), enforces risk checks via CircuitBreaker, and triggers post-mortem on losing trades.
</action>
<acceptance_criteria>
- Orders are blocked when circuit breaker is active or pre-trade memory matches failure pattern
</acceptance_criteria>
</task>

<task id="4">
<title>Test Dual Execution Engine</title>
<action>
Create `tests/test_execution.py`:
- Test VirtualBroker order lifecycle and portfolio tracking
- Test ExecutionEngine risk gatekeeping and broker routing
- Execute with unittest.
</action>
<acceptance_criteria>
- `python -m unittest tests/test_execution.py` exits 0 with all tests passing
</acceptance_criteria>
</task>
</tasks>
